# SPEC.md — PadMapper（仮称）実装仕様

Claude Code向けの実装仕様。機能の背景は `feature-list.md` を参照。
この文書は調査済みの結論と、実装上の判断をまとめたもの。**Web調査は不要。実装と実機検証に集中すること。**

## 0. ゴール
Windows 10/11向けの常駐ソフト。コントローラー（主対象：Flydigi Vader 4 Pro、DInputモード）の入力を読み取り、キーボード/マウス入力に変換する。Steam入力の代替。

### 非ゴール（やらない）
- 仮想コントローラー出力（ViGEmBus、VIIPER、vJoy等）。ただしPhase 7用に差し込み口だけ用意する
- 物理コントローラーを他アプリから隠すこと（HidHide等）
- 外部ドライバー、外部の常駐ツール、Steamへの依存
- パッド内リマップ、スティック値の加工、入力の横取り（仮想パッドなしでは不可能）

## 1. 作業ルール
- 不明点は推測で進めず、**診断機能（8章）で実機から事実を取る**。取れなかった場合は各章のフォールバックに従う
- 純粋なロジック（ジャイロ計算、バインディング判定、プロファイル照合、設定の読み書き）は単体テストを書く
- NuGetは `WPF-UI` と `CommunityToolkit.Mvvm` のみ。追加する場合は理由をコミットメッセージに書く
- 各フェーズ終了時に、完了条件（9章）を満たしたか確認してから次へ進む
- ハードウェア依存の部分は、`IControllerSource` の背後に隠してモック可能にする

## 2. 技術スタック（確定）
- C# / .NET 8、WPF + WPF-UI（Fluent、ダーク/ライト追従）
- 非パッケージ（unpackaged）の通常exeとして配布。インストーラーは後回し
- Win32は P/Invoke（`user32`、`hid`、`setupapi`、`kernel32`）
- タスクトレイは WinForms の `NotifyIcon`（`UseWindowsForms`）
- ログは自前の簡易ファイルロガー（日次ローテーション、7日保持）
- 設定は `%APPDATA%\PadMapper\` 配下にJSON

## 3. アーキテクチャ

```
[Source層]  IControllerSource  → ControllerState（ボタン/軸/ジャイロ）
     ↓
[Engine層]  ProfileResolver → BindingEngine / GyroProcessor → OutputCommand
     ↓
[Output層]  IOutputSink: SendInputSink（キーボード/マウス）
            （将来）VirtualPadSink
```

- `ControllerState`：ボタンのビットセット（論理名で統一：A,B,X,Y,LB,RB,LT,RT,L3,R3,Back,Start,Guide,DPad×4,M1〜M4,C,Z 等）、アナログ軸（正規化 -1..1）、ジャイロ（deg/s）、加速度（任意）、タイムスタンプ
- デバイス固有の解析は `DeviceProfile`（レポート→ControllerState の変換定義）に閉じ込める
- Engineは1スレッドで逐次処理し、UIとはイベント/スナップショットで連携する（UIスレッドをブロックしない）
- `IOutputSink` は抽象化しておく。仮想パッドは**実装しない**が、Phase 7で足せる構造にする

## 4. 入力取得（Source層）
### 方式
- **第一候補：Raw Input**（`RegisterRawInputDevices`、`RIDEV_INPUTSINK | RIDEV_DEVNOTIFY`、専用のメッセージ専用ウィンドウ）。デバイスを排他的に開かず、バックグラウンドでも受信できる
- **フォールバック：HIDデバイスの直接読み取り**（`CreateFile` を `FILE_SHARE_READ | FILE_SHARE_WRITE` で開き、非同期 `ReadFile`）。Raw Inputで必要なレポートが取れない場合のみ
- いずれも**共有（非排他）**で読むこと。ゲームが同じデバイスを読むのを妨げない
- 出力レポート（LED、振動）は**書き込まない**（ゲームとの競合防止）
- 例外：ジャイロ有効化などに初期化コマンドが必要と実機で判明した場合のみ、最小限の書き込みを許可し、その旨を診断画面に表示する

### デバイス検出
- 起動時に列挙し、`WM_DEVICECHANGE` / `WM_INPUT_DEVICE_CHANGE` で抜き差しを検知
- スリープ復帰（`PBT_APMRESUMEAUTOMATIC`）後は再列挙と再登録
- Bluetoothの再接続でも自動復旧

## 5. 出力（Output層）
- `SendInput` を使用。キーボードはスキャンコード（`KEYEVENTF_SCANCODE`）で送る（ゲーム互換性のため）。拡張キーは `KEYEVENTF_EXTENDEDKEY` を付ける
- マウス移動は相対（`MOUSEEVENTF_MOVE`）。小数部は累積して、整数に達した分だけ送る（ジャイロの細かい動きを失わないため）
- 押しっぱなし状態の管理：プロファイル切替、一時停止、終了、デバイス切断時は、**押されているキー/ボタンを必ず全て解放する**
- 一時停止ホットキー（コントローラーのボタン割り当て + キーボード）で、出力を即座に止める

## 6. プロファイルと設定
### 種類
- `Desktop`：フル機能（スティック→マウス、ボタン→キー、モードシフト）
- `Game`（パススルー）：追加出力のみ。UIとバリデーションで、できないことを明示する（`feature-list.md` 参照）

### JSONスキーマ（例）
```json
{
  "version": 1,
  "id": "game-default",
  "name": "ゲーム共通",
  "type": "Game",
  "bindings": [
    { "input": "M1", "trigger": "press",  "action": { "type": "key", "key": "F13" } },
    { "input": "M2", "trigger": "hold",   "holdMs": 500, "action": { "type": "profile", "id": "desktop" } },
    { "input": "C",  "trigger": "double", "action": { "type": "mouseButton", "button": "middle" } }
  ],
  "gyro": {
    "enabled": true,
    "output": "mouse",
    "sensitivityX": 1.0, "sensitivityY": 1.0,
    "deadzoneDps": 0.5, "smoothing": 0.3,
    "accel": { "enabled": false },
    "activation": { "mode": "whileHeld", "input": "LT" }
  },
  "overlay": { "trigger": { "input": "M4", "trigger": "hold", "holdMs": 600 } }
}
```
- `trigger`：`press` / `release` / `hold` / `double` / `chord`（同時押し）。`modeShift` は `Desktop` のみ
- アプリ紐づけ：`rules: [{ "match": { "exe": "game.exe", "titleRegex": null, "path": null }, "profileId": "..." }]`。上から順に評価、先に一致したものを採用。一致しなければデフォルトプロファイル
- 読み込み失敗時は、直前のバックアップ（自動で最新5世代を保持）にフォールバックし、ユーザーに通知する

## 7. 機能要件
### 7.1 ジャイロ→マウス
- 入力：角速度（deg/s）。静止時のバイアスを自動推定して差し引く（一定時間、値がほぼ動かない間の平均）
- 処理順：バイアス補正 → デッドゾーン → スムージング（指数移動平均）→ 加速カーブ → 感度 → マウス移動量
- 軸選択：ヨー/ロール。加速度センサーが取れる場合のみ「プレイヤー空間」を提供、取れなければローカル空間のみ
- 有効化：`always` / `whileHeld` / `toggle`
- 診断画面に、生値と補正後の値のリアルタイム表示を出す

### 7.2 アプリ自動切り替え
- `SetWinEventHook(EVENT_SYSTEM_FOREGROUND)` でフォアグラウンド変化を検知（ポーリングしない）
- プロセスのパスは `QueryFullProcessImageName`（`PROCESS_QUERY_LIMITED_INFORMATION`）で取得
- 切り替え時に押下中の出力を全解放してからプロファイルを入れ替える
- 「いまのアプリに紐づける」：直前の非自アプリのexeを取得してルールを追加

### 7.3 オーバーレイ（Phase 5）
- 最前面、非アクティブ（`WS_EX_NOACTIVATE | WS_EX_TOOLWINDOW`）、フォーカスを奪わない
- 排他フルスクリーンでは表示できない（既知の制限としてUIに明記）
- オーバーレイ表示中に操作する入力は、ゲームにも届く。トリガーとナビゲーションには、ゲームで使われにくいボタン（背面ボタン等）を既定にする

## 8. Vader 4 Pro 対応と診断（Phase 0）
### 前提（調査済み）
- DInputモード（PC/Dinputモード、青LED）で使う。XInputモードでは背面ボタンがOSに出ない
- ポーリングレートはDInputモードで最大約500Hz（XInputで1000Hz）。性能目標はこの前提で設定する
- Flydigi Space Stationのコントローラー内蔵ジャイロモードは**オフ**で使う（併用で問題が出る報告あり）
- 背面4ボタン + C/Zボタンがある
- ヒント（未確認）：Linuxの報告で、Vader 4 ProのUSB IDが VID `0x04B4` / PID `0x2412` と読める記述がある。有線/ドングル/Bluetoothで異なる可能性があるため、**実機の列挙結果を正とする**

### 診断機能（必ず実装）
- 接続中のHIDデバイスの一覧（VID/PID、製品名、Usage Page/Usage、接続経路）
- 選択したデバイスの**生レポートのリアルタイムHEXダンプ**と、前回レポートとの差分ビット強調表示
- 「ボタンを押して、変化したビットを割り当てる」ウィザード（ボタン名→ビット位置の対応表を作り、JSONで保存）
- 同ウィザードの対象：全ボタン、M1〜M4、C、Z、十字キー、スティック、トリガー、ジャイロ
- 解析結果は `docs/vader4pro-report.md` に書き出す

### 背面ボタンの取得に関する判断
- 標準レポートに含まれていればそれを使う
- 含まれていない場合は、独自のレポートID / 初期化コマンドの有無を診断で調べる。必要な初期化コマンドは最小限のみ許可（4章の例外条項）
- どうしても取得できなかった場合は、その状態を診断画面に表示し、背面ボタン対応を未達として報告する（ダミー実装で隠さない）
- 参考：SDLがVaderシリーズの背面ボタンとC/Zに対応している。SDLのソース（オープンソース）の該当ドライバーを読んでよい

## 9. 常駐・起動・権限
- 本体は**管理者権限で動く**（UIPI対策：昇格したウィンドウにも入力を送るため）
- 自動起動：タスクスケジューラのタスク（ログオン時トリガー、`RunLevel=HighestAvailable`、実行時間制限なし、複数起動は無視、失敗時に再起動を最大3回/1分間隔、バッテリー駆動でも開始/停止しない）。**Windows標準のTask Scheduler COMまたは `schtasks.exe`（XMLインポート）**で登録し、外部ツールは使わない
- 設定画面の「ログオン時に起動」のON/OFFでタスクを登録/削除する。登録時のみUAC昇格を要求する（以降はUACなしで自動起動）
- 二重起動防止：名前付きMutex。二重起動時は既存のウィンドウを前面に出して終了
- 未処理例外はログに記録して終了し、タスクスケジューラの再起動設定に任せる
- 診断画面に表示：昇格状態、自動起動タスクの状態、接続デバイス、直近のエラー

## 10. 開発フェーズと完了条件
| Phase | 内容 | 完了条件 |
|---|---|---|
| 0 | 診断（HIDダンプ、Vader解析） | 全ボタン（M1〜M4、C、Z含む）、軸、ジャイロのレポート位置が特定され `docs/vader4pro-report.md` に記録されている。特定できなかった項目は明記されている |
| 1 | 入力取得 + SendInput + トレイ常駐 + 管理者自動起動 | 再起動後にUACなしで自動起動する。ボタン→キー、スティック→マウスが動く。スリープ復帰とコントローラー抜き差しで自動復旧する。押しっぱなしが残らない |
| 2 | プロファイル（Desktop/Game）+ アプリ自動切り替え | exeごとにプロファイルが切り替わる。管理者権限アプリが前面でも切り替わる |
| 3 | ジャイロ→マウス | 静止時にカーソルが流れない。感度/デッドゾーン/有効化条件が設定どおり動く |
| 4 | UI磨き込み | コントローラー図で背面ボタンも含めて割り当てられる。ダーク/ライト追従 |
| 5 | オーバーレイ + コントローラー単独操作 | 背面ボタン長押しでメニューが出て、プロファイル切替/感度/ジャイロON-OFF/一時停止ができる |
| 6 | 他コントローラー（DualSense、DS4、Switch Pro、XInputの読み取り専用） | 各機種でボタンとジャイロが取れる |
| 7（任意） | 仮想パッドバックエンド | ユーザーの判断で着手。`IOutputSink` の実装追加のみで済むこと |

## 11. 性能・品質目標
- 入力から出力まで、通常時 数ms以内（DInputの約500Hzのレポート周期が下限）
- アイドル時CPU 1%未満、メモリは常駐で数十MB程度
- ログは個人情報（ウィンドウタイトル全文など）を残しすぎない。タイトルは設定でON/OFF
- 日本語/英語UI（文字列はリソース化）

## 12. 既知の制限（UIとREADMEに明記する）
- セキュアデスクトップ（UAC、ロック画面）には入力を送れない
- 排他フルスクリーンにオーバーレイは出せない
- アンチチート付きゲームで入力送信がブロックされる場合がある
- ゲーム型では二重入力が起きる（元のボタン入力もゲームへ届く）
- DInputのままで、ゲームがパッドを認識するかはゲーム次第。認識しない場合の運用はユーザーが判断する（そのゲームだけXInputモード、または将来の仮想パッド）
